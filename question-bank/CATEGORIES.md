# コミュニケーションゲーム用カテゴリ一覧

## 整理方針

問題を「出題形式」と「話題テーマ」の二軸で整理する。

- 出題形式：どのような観点で答えるかを表す。個別の問題ファイルは、この単位で分ける。
- 話題テーマ：何について答えるかを表す。各問題の `theme` に付与する。

この構成により、たとえば「経験に関する自己記述文だけを出す」「食に関する問題を複数の出題形式から集める」といった使い分けができる。

すべての問題文は疑問文ではなく、回答者本人の考え、傾向、経験、能力を言い切る自己記述文とする。回答者は、その文が自分に当てはまるかを Yes / No で答える。

## 問題作成時の基準

- 親しい人同士でも初対面でも遊びやすい表現にする。
- 正解を競うカテゴリを除き、回答に優劣が生まれないようにする。
- 恋愛、性別、死、災害、親密さに関する題材はセンシティブ度を付け、レベル2までは利用条件を明示して扱う。
- 性的経験、具体的な死因・命日、被災体験、誰かの犠牲を選ばせる内容など、レベル3相当の題材は避ける。
- 基本的な対象層は大学生相当の知識を持つ30歳前後の参加者とする。
- 相手や一時的な状況を前提にせず、本人の思想や普段の傾向で判断できる内容にする。
- 問題文は疑問符を使わず、「〜したい。」「〜する方だ。」「〜したことがある。」などの自己記述文にする。
- 二択問題は `yesLabel` と `noLabel` を持ち、既存アプリの Yes / No 操作にも対応できる形にする。
- 固有名詞が選択の意味を作る場合は一般化せず、`namedEntities` を付ける。内容が変化しやすいサービスには `timeSensitive` も付ける。
