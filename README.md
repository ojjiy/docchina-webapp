# どっちーな Web App

Yes / Noで答える3段の決定木を使い、代表者の実経路上の回答を参加者が予測するオンラインボードゲームです。GitHub Pagesで配信できる静的アプリとして実装されています。

## ゲームの流れ

1. ホストがルームを作成し、2〜8名が表示名を登録します。
2. 各ラウンドでホストが7問を確認し、必要に応じて同ジャンル内での引き直しまたは文面編集を行います。
3. 代表者以外の参加者は7問すべてへYes / Noを予想し、自信のある段のカテゴリを一つ選びます。提出中は到達点ごとの票数を公開しません。
4. 代表者は、他の参加者が実経路3問のうち何問を当てるか予想します。
5. 全員の予想提出後、代表者が実経路の3問にYes / Noで回答します。回答前には現在の質問に対する全員のYes / No予想を確認でき、Yesは左、Noは右へ進みます。
6. 質問ごとの正解点に、全問一致・自信・単独正解・少数正解のボーナスを加算します。結果発表では実経路の各質問にYES／NOの予想者アイコンを表示します。代表者も正解数予想が一致した人数に応じて得点します。全員が一度ずつ代表者を務めると終了します。

ゲーム中に参加したユーザーは現在のラウンドを観戦し、次のラウンドから予測へ参加します。代表者キューの末尾にも追加されます。最終結果では、各ラウンドの正解数と得点、および各代表者が回答した3問とYes / Noの履歴を確認できます。

## 得点設定

得点は [`game-config.js`](./game-config.js) で管理しています。初期値は質問正解5点、全問一致10点、自信5点、単独正解10点、少数正解5点、代表者の正解数予想は1人につき3点です。ゲーム開始時の設定値をルームへ保存するため、進行中に配信側の設定を変更しても、そのゲームの得点は変わりません。

単独正解と少数正解は実経路上の質問ごとに判定し、重複しません。正解者が1人の場合は単独正解を優先し、正解者が2人以上かつ予想者の半数未満の場合は少数正解とします。予想者が1人だけの場合、人数に応じたボーナスは付きません。

## ローカル起動

ES Modulesと`questions.json`の読み込みにHTTPアクセスが必要なため、ファイルを直接開かずローカルサーバーを使用してください。

```sh
uv venv .venv
npm run serve
```

ブラウザで `http://localhost:4173` を開きます。Firebase未設定時はlocalStorageモードになり、同じブラウザの複数タブで同期を確認できます。

## テスト

```sh
npm test
```

木の経路計算、ジャンル割当、全ノード予想、各種ボーナスを含む採点、問題データなどの純粋ロジックをNode.js標準テストランナーで確認します。

## Firebase設定

1. FirebaseプロジェクトとWeb Appを作成し、Firestoreを有効にします。
2. `firebase-config.js` の `window.DOCCHINA_FIREBASE_CONFIG` にWeb App設定を記入します。FirebaseのWeb設定値はクライアントへ配布される識別情報であり、管理者秘密鍵ではありません。
3. `firestore.rules` をデプロイし、reCAPTCHA Enterpriseを利用するApp Checkを有効化します。
4. App Checkの許可ドメインへローカル確認用ドメインとGitHub Pagesのドメインを追加します。
5. FirestoreのTTLポリシーを `rooms` コレクショングループの `expiresAt` フィールドへ設定します。各ルームは最終操作から7日後を期限として保存します。

本アプリは厳密なユーザー認証を行わない、親しい参加者間のゲームを想定したMVPです。予測内容は通常UIでは名前を秘匿しますが、悪意ある参加者によるFirestoreへの直接アクセスを防ぐものではありません。

## GitHub Pages

ビルド工程はありません。GitHubリポジトリのSettingsからPagesを開き、`Deploy from a branch`、`main`、`/(root)`を選択します。共有URLはパスルーティングを使わず、`?room=ABC234` の形式で生成されます。

## 質問データ

`questions.json` は8ジャンル×16問のサンプルです。構造は次のとおりです。

```json
{
  "version": 1,
  "genres": [
    {
      "id": "genre-id",
      "label": "表示名",
      "questions": [{ "id": "unique-question-id", "text": "Yes / Noで答えられる質問" }]
    }
  ]
}
```

各問題IDはファイル全体で一意にしてください。現在の3段・最大8ラウンドのジャンル割当では、各ジャンル7問以上が必要です。現在のサンプルは将来の調整余地を含めて各16問を維持しています。

今後の問題選定用として、`question-bank/` に「出題形式」と「話題テーマ」の二軸で整理した11カテゴリ・各16問以上の問題リストがあります。カテゴリ定義と利用方法は [`question-bank/README.md`](./question-bank/README.md) を参照してください。現在のアプリが読み込む `questions.json` とは分離しているため、内容をレビューしてから採用できます。
